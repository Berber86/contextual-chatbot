# Коучинг целей пользователя — спецификация

**Статус:** итог 4-этапного брейншторма, решения зафиксированы.
**Ветка:** `arena/5089ca9c-contextual-chatbot`, база — `main` после PR #10 (эмуляция личности).

**Состояние реализации:**

| Инкремент | Что | Статус |
|---|---|---|
| 1 | «Цели как объект»: хранение, миграция, окно «Цели», чек-ины, архив, экспорт/импорт | готово (PR #11) |
| 2 | «Коучинг в чате»: цель в промпте, `get_user_goals`, лимит вопросов, кризис-переключатель, приоритет над образом, выключатель | готово |
| 3 | «Профиль и обзор»: производство профиля, экран профиля, тихий дрейф ±1 с журналом, недельный обзор | готово |
| 4 | «Черновик шага из чата»: бот предлагает формулировку, человек ставит её кнопкой; запись делает клик, а не модель | готово |

---

## 1. Продуктовая рамка

Функция: бот подстраивается под психологию пользователя, чтобы помогать ему двигаться
к целям, которые пользователь поставил **сам**.

Пять принципов (нарушение любого — дефект, а не «стиль»):

1. **Цель принадлежит пользователю.** Бот может предложить черновик, но не создаёт,
   не меняет и не закрывает цели сам.
2. **Подстройка — про форму, не про стандарты.** Меняются тон, размер шага, ритм и тип
   обратной связи. Факт застоя не смягчается, цель не отменяется.
3. **Никакого трекера.** Нет процентов, стриков, очков и оценок пользователя.
4. **Прозрачность.** Профиль подстройки виден, объясним и редактируем.
5. **Самоотчёт важнее вывода.** Слова пользователя сильнее любой догадки модели.

## 2. Модель данных

Ключи в стиле проекта (`chatbot_*`), каждый — объект с `version` для миграции
(миграция встраивается в существующий `runMigration` в `ui.js`).

```js
goals:        'chatbot_goals',            // { version, goals: [...] }
goalCheckins: 'chatbot_goal_checkins',    // { version, checkins: [...] } кап 200
goalReviews:  'chatbot_goal_reviews',     // { version, reviews: [...] }  кап 52
coachProfile: 'chatbot_coaching_profile'  // { version, params, changelog, enabled }
```

```js
// Цель
{
  id: 'goal_...',
  title: '',            // формулировка пользователя
  why: '',              // зачем — обязательно, словами пользователя
  success: '',          // «как пойму, что получилось» — обязательно, качественно
  horizon: 'week|month|quarter|open',   // опционально, по умолчанию 'open'
  status: 'active|paused|done|dropped',
  nextStep: { text: '', createdAt: 0 }, // ровно один шаг
  doneSteps: [{ text: '', at: 0 }],
  source: 'user|suggested',
  createdAt: 0, updatedAt: 0,
  archivedReason: ''    // «снял с паузы», а не «провалил»
}

// Чек-ин — самоотчёт, не измерение
{ id, goalId, at, state: 'moved|stuck|no_time', wentWell: '', obstacle: '' }

// Недельный обзор
{ id, weekKey: '2026-W44', goalId, movement: '', obstacle: '', nextStep: '', createdAt: 0 }
```

**Лимиты:** `LIMITS.goals = 20` (кап хранения), `GOALS_CONFIG.activeWarn = 3`
(предупреждение, не блокировка), `checkinsCap = 200`, `reviewsCap = 52`,
`reviewEveryDays = 7`.

**Разграничение сущностей** (фоновая аналитика не имеет права превращать одно в другое):

| Сущность | Что это | Может стать целью |
|---|---|---|
| План в хронологии | факт из жизни | нет, максимум подсказка по кнопке |
| Пробел в знаниях | чего не знает бот | нет |
| Гипотеза | догадка о мотивах | нет, никогда автоматически |
| Ценность из `you.js` | не подключаем (решение пользователя) | — |

## 3. Жизненный цикл

1. **Создание.** Название → помощник формулирует «зачем» 2–3 наводящими вопросами →
   критерий готовности. Срок не требуется.
2. **Шаг.** Ровно один следующий шаг; сделанное уходит в `doneSteps`.
3. **Чек-ин.** «Сдвинулось / застряло / не было времени» + короткая заметка. Без вызова
   модели: состояние выбирается в один тап.
4. **Застревание (2 чек-ина подряд без движения)** — триаж:

   | Что в заметках | Действие |
   |---|---|
   | внешнее препятствие (время, ресурсы, другие люди) | уменьшить шаг |
   | сомнение в цели («не моё», «не вижу смысла») | вернуть «зачем», спросить про продолжение |
   | смешанные сигналы / нет данных | спросить причину (дефолт) |

5. **Тишина 3+ недели** — мягкая ревизия одним вопросом: важна / поменять шаг / снять.
   Все три ответа равноправны, стыда нет.
6. **Завершение** — `done` или `dropped` с причиной. Оба состояния нормальны.

## 4. Профиль подстройки

Шесть параметров, все видимые в интерфейсе с объяснением «почему так» и свидетельствами.

| Параметр | Значения | Откуда | На что влияет |
|---|---|---|---|
| Прямота | мягко / нейтрально / прямо | стиль, фидбек после чек-инов | как говорить о застое |
| Структура | свободно / средне / пошагово | как формулирует цели и отвечает | шаг или вопрос-исследование |
| Размер шага | микро / обычный / крупный | `moved` vs `stuck` | «10 минут» против «выдели блок» |
| Глубина рефлексии | к действию / средне / сначала разобраться | гипотезы, темы сообщений | задавать ли «почему» перед шагом |
| Ритм касаний | редкие глубокие / регулярные короткие | частота заходов и ответов на чек-ины | частота упоминаний цели |
| Обратная связь | за процесс / за результат | реакция на поддержку, «зачем» | хвалить за шаг или за итог |

### Обновление профиля

- **Может меняться молча (±1):** шаг, глубина рефлексии, ритм, обратная связь.
- **Только с подтверждением:** прямота (меняет то, как с человеком говорят).
- Каждое изменение → запись в `changelog` с датой и причиной.
- Раз в неделю — короткая сводка: «подстроил шаг и ритм, вот почему». Тихая подстройка
  не значит бесследная.

### Ссылки на психологию в речи (решение пользователя: свободно)

Разрешено, но с обязательными рамками:

- допустимо опираться на черты, гипотезы и наблюдения в живой речи;
- при первом психологическом утверждении в контексте цели — маркер догадки
  («мне кажется», «похоже») и приглашение поправить;
- **запрещено:** ставить ярлыки и диагнозы; использовать психологию как давление
  или ограничение выбора («ты же перфекционист, тебе будет тяжело — не начинай»);
- **приоритет источников при конфликте:** поправка пользователя > его слова >
  наблюдение поведения > вывод модели.

### Запрещённые рычаги

Стыд, страх, искусственная срочность, «а в прошлый раз ты не сделал», переменное
подкрепление, геймификация. Проверяется в промпте **и** в тестах.

### Приоритет режимов

Коучинг > эмуляция личности: образ задаёт манеру, но не мешает помочь и не может
запретить коучинговый вопрос. Режим инсайтов влияет на способ работы с памятью,
не на структуру хода.

### Дистресс и кризис

При явных признаках тяжёлого состояния коучинг выключается, включается поддержка.
При кризисных сигналах — без коучинговых вопросов, мягкая рекомендация специалиста.
Проверяется в коде (до инъекции коучингового блока), не только промптом.

## 5. Интерфейс

Отдельный пункт навигации **«Цели»** и собственное окно по образцу «Самопознания»
и «Отчётов»:

- **Список** — активные, на паузе, архив; пустое состояние с одной кнопкой «Поставить цель».
- **Карточка цели** — «зачем», критерий готовности, следующий шаг, чек-ин в один тап,
  история шагов, действия: пауза / завершить / снять.
- **Обзор недели** — pull-поверхность: появляется, когда обзор готов. В чате бот может
  упомянуть его **один раз** и только при наличии активных целей.
- **Профиль** — шесть параметров, «почему так», журнал изменений, полный выключатель
  подстройки.
- **Экспорт/импорт JSON** — страховка от потери `localStorage`.

| Файл | Содержимое |
|---|---|
| `app.js` | ключи, `GOALS_CONFIG`, CRUD целей и чек-инов, профиль + changelog, `getGoalsForPrompt`, миграция |
| `goals.js` (новый) | модуль UI: навигация, список, карточка, чек-ин, обзор, профиль, экспорт |
| `analytics.js` | `runGoalWeeklyReview()` (1 вызов в неделю на пользователя), `classifyGoalStuck()` (эвристика + LLM только при неоднозначности), `applyCoachDrift()` (локально) |
| `ui.js` | tool `get_user_goals`, блок «активная цель + шаг» в системный промпт, лимит коучинговых реплик, кризис-переключатель |
| `index.html`, `styles/` | пункт навигации, окно модуля, стили |
| `tests/goals.test.cjs` | схема и миграция, жизненный цикл, триаж, границы дрейфа, инъекция в промпт, гейт обзора, кризис-переключатель, отсутствие процентов в данных |

Жёсткие правила — в коде и тестах, а не только в тексте инструкции:
одна коучинговая реплика за ход, не более одного вопроса о цели за три сообщения,
обязательные «зачем» и критерий готовности.

## 7. Порядок поставки (три инкремента)

**Инкремент 1 — «Цели как объект», без чата**
Хранение, миграция, модуль «Цели», создание с помощником формулировки, карточка,
чек-ины, архив, экспорт/импорт.
*Готово, когда:* цель создаётся и переживает перезагрузку, чек-ин отмечается в один тап,
история видна, в данных нет ни одного процента.

**Инкремент 2 — «Коучинг в чате»**
Tool `get_user_goals`, блок цели в промпте, лимиты реплик, кризис-переключатель,
приоритет над образом.
*Готово, когда:* бот знает цель и следующий шаг, предлагает шаг в манере роли,
не спрашивает чаще лимита, при кризисе не коучит.

**Инкремент 3 — «Профиль и обзор»**
Производство профиля из памяти и чек-инов, экран профиля, тихий дрейф в разрешённых
границах + журнал, недельный обзор и его pull-поверхность.
*Готово, когда:* профиль объясним и редактируем, дрейф не выходит за ±1 и пишется
в журнал, обзор появляется не чаще раза в 7 дней.

## 8. Метрики и критерий отката

Наблюдаем полезность, а не вовлечённость:

- доля целей с определённым следующим шагом;
- доля целей, доживших до второго чек-ина;
- открытия недельного обзора;
- добровольные правки профиля (признак, что его читают);
- жалобы на навязчивость.

**Откат:** если медиана чек-инов на цель меньше одного за две недели — механика слишком
тяжёлая. Убираем или упрощаем, а не «улучшаем тексты».

## 9. Зафиксированные разногласия

Решения приняты пользователем, ниже — риски, которые я продолжу отслеживать.

1. **Свободные ссылки на психологию.** Риск: уверенный промах («ты интроверт») рушит
   доверие, накопленное памятью. Митигация: маркер догадки при первом утверждении,
   обязательная поправка пользователем с приоритетом над выводом, запрет на давление.
2. **Тихая подстройка всех параметров, кроме прямоты.** Риск: через месяц человек
   общается в тоне, причин которого не помнит. Митигация: журнал изменений и недельная
   сводка «что я подстроил и почему».
3. **Отказ от ценностей «Самопознания».** Риск: подстройка опирается на выводы модели
   сильнее, чем на заявленные ценности. Митигация: приоритет самоотчёта и порог
   достоверности (≥3 записи с уверенностью medium+ и цитатами).
