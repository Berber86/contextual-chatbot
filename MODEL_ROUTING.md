# Маршрутизация по сложности (System One: jev / solar-decide)

Дешёвая модель решает, **какой моделью отвечать**. Решение — одно типизированное
число от 0 до 1, без генерации текста. Ошибка маршрута стоит копейки, поэтому
страховка простая: любая проблема → `null` → работаем ровно как раньше.

Тем же запросом решаются ещё три вещи (state один, цена та же):

| Вопрос | Тип | Что заменяет |
|---|---|---|
| `archetype` | `choice` (8) | `pickResponseArchetype()` — раньше `Math.random()` |
| `ask_question` | `noul` | `decideQuestionPolicyForThisTurn()` — раньше 12% случайно |
| `needs_memory` | `noul` | задел для стадии 1 (пока только логируется) |

Порог вопроса — 0.5. Приоритеты: режим `ASK_ME` важнее модели, модель важнее случая.
Инструкции архетипов дословно совпадают с прежними строками из `ui.js` — промпт
стадии 2 не меняется, меняется только способ выбора.

## Контракт

`POST {base}/v1/systemone` (Hydra), тело:

```js
{
  model: 'jev-1.14',              // или 'solar-decide'
  state: { message, recent },     // одна общая точка контекста
  questions: {
    complexity:    { type: 'score', instructions: '…', criteria: [10 уровней] },
    needs_memory:  { type: 'noul',  instructions: '…' }
  }
}
```

Ответ: `answers.complexity.score` (0…9) и `answers.needs_memory.noul` (0…1),
плюс `confidence` и `usage`. Выходные токены бесплатны у обеих моделей.

| Модель | Вход | Контекст в каталоге Hydra |
|---|---|---|
| `jev-1.14` (TypeSafe) | 2,70 ₽ / 1M | 260 000 |
| `solar-decide` (Upstage, beta) | 1,00 ₽ / 1M | 500 000 |

Переключатель провайдера: `localStorage.chatbot_systemone_provider` = `jev` | `solar`
(по умолчанию `jev`). Ключ на сервере: `HYDRA_API_KEY` в `/api/systemone`.

## Уровни и модели

| Сложность | Уровень | Куда идёт ответ |
|---|---|---|
| `< 0.5` | easy | цепочка OpenRouter (`nvidia/nemotron…`), Hydra — только если цепочка упала |
| `0.5 … 0.79` | medium | Hydra `glm-5.2` |
| `≥ 0.8` | hard | Hydra `hydra-gemini-pro` |

Пороги — в `SYSTEMONE_CONFIG.thresholds` (`jev.js`). Модели уровней — в
`pickRouteByComplexity`, там же меняются без правок остального кода.

## Когда маршрут не работает

- Нет платного провайдера (`isSmartMode()` и `isFullHydraMode()` ложны) — все ходы
  идут прежним путём: в бесплатном режиме менять нечего.
- Выключатель: `localStorage.chatbot_route_complexity = '0'`.
- `jev.js` не загрузился — `resolveTurnRoute` не вызывается вовсе.
- Сеть, таймаут (2,5 с), мусор в `answers`, `score` не число — `null`, прежняя модель.

## Стоимость

Один запрос ≈ 400–800 входных токенов ≈ **0,001–0,002 ₽**. Замер в коде:

```js
getSystemOneStats()
// { calls, errors, cacheHits, byProvider, tokens, provider, estimatedRub }
```

Одинаковые состояния кэшируются (до 200 записей), повторный ход по тому же
сообщению денег не тратит.

## Облака памяти (выбор темы для второй стадии)

Перед сборкой контекста jev решает, **какие темы памяти поднять** в этом ходу.
Тема (облако) — это весь срез профиля: факты, черты, хронология, люди, гипотезы и
пробелы, помеченные одним `cloud`. Выбор — один запрос на ход: по одному вопросу
`noul` на облако, `threshold = 0.45`, максимум `4` облака (`CLOUD_CONFIG` в `app.js`,
`selectCloudsForTurn` в `jev.js`). Отдельного вопроса «нужна ли память» нет: если ни
одно облако не прошло порог, вторая стадия получает явную строку «память не
поднималась» вместо досье.

- Дёшево: тот же один вызов, что и раньше, ≈ **0,005 ₽ / 0,3–0,5 с** против
  ≈ **0,15–0,2 ₽ / 1,5–4 с** у сжатия досье.
- Контекст второй стадии — только выбранные облака, по `itemsPerCategory = 12`
  записей на категорию, блоки `=== ОБЛАКО «Имя» ===`.
- Флаг: `localStorage.chatbot_cloud_memory` (`'0'` — выключить), по умолчанию включён.
  Выключен, меньше двух облаков или ошибка выбора — работает прежнее сжатие досье.
- Записи без облака попадают в служебное «Разное». Первичная разбивка старой памяти
  делается один раз в фоне и ставит `bootstrappedAt` даже при сбое, чтобы не
  повторяться каждый ход.
- Превью «мыслей» (`micro_opening`) убрано: интерфейс беднее, зато без лишней
  генерации.

## Проверки

`tests/clouds.test.cjs` — дедупликация имён (регистр, ё), «Разное», присвоение облака,
изоляция контекста по выбранным облакам, порог 0.45 и максимум 4, один запрос на ход,
порядок «облака → длина → сжатие», отсутствие `micro_opening`, переименование облака,
однократность первичной разбивки.

`tests/routing.test.cjs` — контракт запроса (четыре вопроса), переключение провайдера,
границы 0.5 / 0.8, нормализация шкалы, порог вопроса 0.5, совпадение архетипов с
прежними строками `ui.js`, кэш, таймаут, отказ сети, подстановка модели в стриминг,
порядок «OpenRouter → Hydra» на лёгком маршруте, гейт по режиму и флагу.

Дев-сервер отвечает на `/api/systemone` демо-значением по грубой эвристике
(`SYSTEMONE_DEV_FORCE=0.85` фиксирует сложность) — чтобы все три уровня можно было
увидеть без ключа. В проде за это отвечает сама модель.
